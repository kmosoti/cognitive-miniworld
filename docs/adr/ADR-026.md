# ADR-026 — Complete episodic traces and explainable contextual retrieval

**Status:** accepted · **Date:** 2026-08-28 · **Source:** MW-040

## Context

MW-040 must preserve every public value needed to inspect a completed
predictive loop, explain why a prior episode was retrieved, and demonstrate
that retrieval can improve a later decision. The existing `ExperienceTrace`
contract already names context, belief, references, proposals, predictions,
decision, outcomes, error, provenance, uncertainty, and future eligibility.
It intentionally stores links rather than the linked values, so an agent-side
record must retain the complete immutable public object graph alongside that
contract. No contract schema change is required.

## Decision

An `EpisodicRecord` contains the canonical `ExperienceTrace` plus the complete
`BeliefState`, sorted reference trajectories, sorted action proposals, one
prediction per proposal, selected `ActionDecision`, ordered public outcome
observations, and typed `ErrorBundle`. Context feature names are sorted and
unique. Every cross-reference is checked: predictions identify the recorded
belief and proposals, the decision identifies and agrees with one proposal,
and every trace ID agrees with its linked value. Trace provenance is the sorted
union of every input provenance, outcome event ID, and error event ID; trace
confidence is the minimum input confidence. Eligibility remains empty because
causal weighting is MW-041 scope.

The recorder is immutable and keeps at most 256 records. Records are ordered
by `(tick, trace_id)`, duplicate trace IDs are rejected, and capacity pressure
retains the newest keys regardless of insertion order. One record may contain
at most 64 context features, 16 references with 64 points each, 64 proposals,
64 predictions with 64 outcomes each, 64 public outcome observations, 256
belief hypotheses, and 64 features per item. Each trace may scan at most
10,000 source-event IDs and 65,536 abstract work units. All limits are checked
before provenance union or record construction, and persisted nested values
are deep-validated at every boundary where a value can come into existence
(construction, decode, convert, replace) and at the outbound encode boundary;
ADR-027 records why in-process revalidation of already-constructed frozen
values was removed and how the retrieval work charge is split.

Retrieval compares the union of query and record feature names. An exact
`FeatureValue` contributes one point; conflicts, query-only features, and
record-only features contribute zero. Similarity is exact matches divided by
the feature-name union. Each returned match carries all four relation types as
applicable, making its score inspectable. Zero-score records are omitted;
positive matches are ordered by descending score, descending episode tick,
and ascending trace ID. Queries return at most 32 records and scan at most
65,536 abstract work units. Retrieval supplies evidence to a decision process;
it never substitutes remembered state for current belief.

The confirmatory fixture uses named stream
`experiment:episodic-memory:context` to vary one of eight cues and the optimal
member of `{adapt, wait}`. Every seed records a successful old-regime episode
and a successful current-regime episode sharing the cue. The live query names
the current regime, so its episode scores `1.0` while stale history scores
`0.5`. An evaluator-only adapter selects the top episode's action and compares
binary decision quality with the fixed no-retrieval `wait` policy. Across
seeds 1000–1099, mean decision delta must be at least `0.4`, stale selection
rate must be `0.0`, and the minimum selected-match score must be `1.0`.

## Consequences

Fast acquisition remains sparse, bounded, inspectable, and separate from
semantic rewriting. MW-041 can add eligibility to the same trace identity,
while consolidation remains MW-042 scope. The contextual score is deliberately
simple and exact; learned embeddings, temporal decay, consolidation, and
policy arbitration require separate decisions. The confirmatory adapter proves
retrieval usefulness in one paired contextual-choice gate and is not a general
action arbitrator or a claim of optimal memory search.
