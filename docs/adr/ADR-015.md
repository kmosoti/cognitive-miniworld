# ADR-015 — Python 3.14.7 free-threaded runtime and concurrency boundary

**Status:** accepted · **Date:** 2026-08-27 · **Source:** MW-001 uplift

## Context

The original Python 3.12 baseline predates CPython's supported
free-threaded build. ViabilityGrid will eventually run many independent
scenario, seed, and candidate combinations; those runs are a natural
parallel boundary, while concurrency inside a tick would make ordering,
randomness, and replay harder to audit.

## Decision

CPython 3.14.7 free-threaded (`3.14.7t` in `uv`) is the required primary
development and CI runtime. Conventional CPython 3.14.7 remains a CI
compatibility lane. CI verifies both the build capability and live GIL
state after native imports, because an incompatible extension may
re-enable the GIL.

Concurrency is permitted only across isolated `(scenario, seed,
variant)` runs. A world tick and an episode remain single-threaded;
workers share no mutable world, primitive, RNG, iterator, or log. Batch
results are reassembled in stable input order, and worker count or
scheduling never enters behavioral digests. Wall time is diagnostic
only.

Dependencies retain modern minimums and an exact `uv.lock`. The project
does not float interpreter or package versions in the name of staying
current; upgrades are explicit, gated, and committed.

## Consequences

Free-threaded correctness and relative 1→2→4 scaling are CI gates.
Single-thread execution remains the reference until representative M0
episodes prove a threaded default preserves event and terminal hashes
and improves throughput. Run manifests will record interpreter build,
ABI, GIL state, executor, and worker count separately from behavioral
digests.
