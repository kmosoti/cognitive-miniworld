# ADR-011 — Viability, operationalized

**Status:** accepted · **Date:** 2026-08-27 · **Source:** KICKOFF

## Context

"Viability" must be a number the metrics layer can compute from the
event log, not a vibe. The source schematic treats it as headroom
rather than a threshold, and Milestone 2 promotes dynamic references
only if they improve that headroom without more irreversible errors.

## Decision

Each regulated resource `r` (energy, integrity) lives in `[0, max_r]`.

- **Hard floor:** any tick with `energy <= 0` or `integrity <= 0` is a
  terminal state and ends the episode.
- **Soft band:** a preregistered `[0.2*max_r, 0.9*max_r]` per resource.
- **Margin:** `m_r(t) = min(x_r - soft_floor_r, soft_ceil_r - x_r) / max_r`;
  overall viability margin `V(t) = min_r m_r(t)`.
- **Metrics:** `time-outside-viability` = count of ticks with `V(t) < 0`;
  `viability-auc` = mean of `max(V(t), 0)` over the episode.

## Consequences

`V(t)` is signed: negative means outside the soft band but still alive,
so the agent has a graded signal before the hard floor. Both metrics
compute from the event log alone (MW-006). The soft band is
preregistered per scenario and frozen before benchmark runs (ADR-008).
