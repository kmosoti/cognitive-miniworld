# ADR-001 — Python reference implementation before Rust optimization

**Status:** superseded by ADR-015 · **Date:** 2026-08-27 · **Source:** EPIC §16

This record preserves the original MW-001 decision. ADR-015 replaces
its interpreter baseline while retaining Python as the reference
implementation language.

## Context

The deliverable is an experimental harness, not a fast simulator. The
expensive resource is the time it takes to change an experiment, not
the time it takes to run one. A tiny grid world with tabular
primitives is not obviously compute-bound, and EPIC §4 lists a Rust
port as a non-goal absent evidence.

## Decision

Python 3.12+ is the implementation language for the whole system. No
Rust, Cython, or native extension is introduced without a profile
showing a stable, dominant hotspot on a realistic benchmark run, and an
ADR recording that profile.

## Consequences

Experiments stay cheap to write and read. If benchmark volume later
makes the kernel the bottleneck, the pure `transition` function
(EPIC §5.6) is the natural first port and its purity makes it
differentially testable against the Python original.
