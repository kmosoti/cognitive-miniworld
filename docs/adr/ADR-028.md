# ADR-028 — Forecast-bound dynamic references and demand-shift gate

**Status:** accepted · **Date:** 2026-08-28 · **Source:** MW-020

## Context

MW-020 replaces the static reference used by the first closed-loop spine with
a context-sensitive trajectory. ADR-014 froze the output shape and requires a
trajectory to identify the state estimate and forecast that produced it. The
knowledge graph named only `BeliefState` and `ResourceBudget` as inputs even
though the issue acceptance criteria require predicted demand and distinct
forecast provenance. A belief has a revision tick but no forecast horizon, so
encoding a future prediction inside it would erase the distinction that the
acceptance criterion is intended to preserve.

The canonical `demand_shift` fixture is already part of M0 evidence. Its own
default primary metric remains viability AUC; changing that manifest would
invalidate its digest and confound MW-020 with a changed world. The MW-020
experiment therefore needs its own frozen comparison identity.

## Decision

`DynamicReferenceGenerator.generate` consumes a current `BeliefState`, a
matching future `PredictionDistribution`, and a same-tick `ResourceBudget`, and
emits the existing `ReferenceTrajectory`. The knowledge graph is corrected to
name `PredictionDistribution` as the third input. No public contract schema is
changed.

Let `C` be the positive energy capacity declared by the budget, `x` the
belief-weighted current `energy`, and `d` the forecast-weighted positive
`ambient_demand`. The first generator uses

```text
target = clip[0,C](B C + H C d + G max(0, S C - x))
```

with preregistered defaults `B = 0.30`, `H = 0.05`, `G = 0.25`, and
`S = 0.60`. Tolerance is `0.10 C`, the point horizon is the forecast horizon,
and priority is `min(1, d / 4)`. Thus greater predicted demand cannot lower the
target, while lower current energy cannot lower the state-correction term.
Clipping preserves the contract range without allowing an unbounded forecast
to create an impossible target; demand above the configured maximum of `4.0`
is rejected rather than silently clipped.

The belief, forecast, and budget must be cross-linked, bounded, and affordable:
forecast belief ID matches the input belief, budget tick matches the belief
revision, the horizon is strictly future, relevant features are unique on
positive-probability items, and charged scan/construction work must fit both a
fixed 65,536-unit ceiling and the supplied compute budget. Reference confidence
is the minimum input confidence. Provenance is the sorted union of all three
inputs' public source-event IDs. The canonical trajectory ID byte-length frames
the exact belief and forecast IDs before the horizon, making the generating
contracts unambiguous and inspectable even when an input ID contains a framing
delimiter; provenance retains their underlying evidence.

The confirmatory experiment binds the unchanged canonical `demand_shift`
manifest and the registered `0.55` reactive fixed-setpoint baseline. An
agent-side experiment adapter turns the visible `predictable-weather` cue into
a five-tick, constant-demand forecast of `2.0`; otherwise it forecasts the
currently observed demand. It consumes only when a resource is publicly
present and forecast energy falls below the generated reference. The adapter
is pure, records the belief, forecast, reference, target, demand, horizon, and
an algebraically isolated same-belief no-warning target in the public action
proposal, and never reads the hidden schedule. That counterfactual isolates
forecast sensitivity from ordinary state depletion without changing the
selected action or running a second agent-side reference computation.

Across benchmark seeds 1000–1099, the primary paired effect is baseline minus
candidate `time-outside-viability` and must be at least one tick for every
seed. Candidate viability AUC must be noninferior with margin `0.0`,
irreversible errors must not increase, and the reference-triggered consume must
occur before hidden demand-shift tick 12. The gate also requires at least a
`5.0`-unit target increase when the forecast changes at fixed nearby state and
at least a `0.5`-unit increase as state depletes under the same warning
forecast. These secondary checks prevent a nominally dynamic implementation
from passing with a constant target.

## Consequences

MW-020 composes the existing estimator/forecast/reference contracts without
changing the M0 fixture or exposing evaluator truth. The cue-to-demand mapping
is a deliberately narrow preregistered experiment hypothesis, not a general
weather model. New demand variables, learned cue mappings, multiple horizons,
or a different target equation require a new decision record. The static
controller remains an executable ablation, and MW-021 may replace outcome
valuation without changing the trajectory schema.
