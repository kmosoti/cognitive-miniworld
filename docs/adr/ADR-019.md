# ADR-019 — Executable baseline and evidence identity boundary

Status: accepted

## Context

Milestone 0 originally had three shallow seams that could make plausible
evidence ambiguous. A fixture-to-baseline table did not prove that its names
resolved to callable implementations, a component version did not distinguish
two differently configured instances, and `frozen=True` could still be bypassed
on nested public values with `object.__setattr__`. The demand-shift oracle also
must not become eligible merely because an arbitrary manifest reuses its label.

## Decision

Every baseline ID in first-wave coverage resolves through a closed constructor
to a concrete implementation. An evaluator-side interface probe invokes every
declared implementation using immutable public contracts and named RNG streams.
This probe establishes ablation availability; it does not fabricate a later
candidate's predictions, credits, attention decisions, confidence estimates,
or corresponding primary metric. Those confirmatory metrics land with the
milestone that can emit their required evidence. Milestone 0's scientific gate
remains the preregistered demand-shift viability-AUC comparison.

Experiment policies expose sorted, unique `FeatureValue` configuration tuples.
Their canonical digest is recorded in the replay manifest and included in the
shared comparison contract alongside both baseline and oracle family identity.
The scenario digest remains a separate shared comparison input. The oracle is
eligible only for the exact canonical demand-shift fixture digest and its
one-tick wait/consume assumptions.

Active public stimuli are materialized from isolated `stimulus:<id>` streams and
included in agent observations. Evaluator-only stimulus and habit schedule
records are processed without leaking hidden declarations to the policy.
All concrete public contract values and the complete transitive scenario view
are hardened against low-level attribute replacement while preserving canonical
encode/decode round trips.

The M0 gate consumes typed run pairs and validates the exact fixture, seed tier,
variants, pair identities, declared metric direction and threshold, safety
metric, and frozen bootstrap configuration before computing a verdict. It
recomputes the deterministic bootstrap and exact RNG continuation from the
per-seed evidence before serialization. Batch execution rejects excessive
per-run and aggregate horizon, stimulus, evaluator-schedule, and hidden
world-schedule work before compilation or worker creation; stimulus intensity
changes advance through one evaluator-owned immutable cursor.

## Consequences

Coverage, pairing, configuration, oracle eligibility, and public immutability
are executable claims rather than naming conventions. A new policy parameter,
fixture change, or analysis setting necessarily changes or invalidates evidence
identity. Metrics whose causal inputs do not exist yet remain explicitly
unclaimed instead of being approximated by convenient telemetry.
