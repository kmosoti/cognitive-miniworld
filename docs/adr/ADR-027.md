# ADR-027 — Validation at trust boundaries and derived retrieval bounds

**Status:** accepted · **Date:** 2026-08-28 · **Source:** M1 optimization
(MW-014/MW-040 deliverables, pre-merge)

## Context

The MW-014 arbitrator and MW-040 recorder revalidated every nested value at
every operation: each `EpisodicRecorder` construction re-ran `__post_init__`
for all stored records, retrieval deep-validated the whole store twice, and
`arbitrate` re-ran `__post_init__` for every nested input object. The intent
was defense in depth. The measured consequence was that storage cost grew
quadratically in occupancy: filling the recorder to its own declared capacity
of 256 took 10.1 seconds (~n^1.9), one query took 92ms, and profiling showed
`EpisodicRecord.__post_init__` running 18,720 times for 192 stores.

The defense was also aimed at the wrong boundary. msgspec runs
`__post_init__` on construction, decode, convert, and replace, so every path
by which a struct can come into existence already deep-validates it, and the
structs are frozen afterwards. In-process revalidation of an
already-constructed value therefore re-checks what cannot have changed; the
only thing it can catch is deliberate in-process mutation through
`force_setattr` or `object.__setattr__`, which is self-sabotage, not input.

A second, logical defect compounded this: storage admitted records whose
aggregate validation work made every later query exceed the fixed retrieval
work limit of 65,536 units. A memory legitimately filled to capacity with
records of at most 64 work units was one query away from permanent
`ValueError`; richer admitted records made the whole store unqueryable.

## Decision

Validation happens where trust is actually gained or lost, and nowhere else.

Construction, decode, convert, and replace deep-validate — that is msgspec's
own behavior and every type's `__post_init__` remains complete for its own
direct contents and cross-references. `EpisodicRecorder` validation is
shape-only: capacity, element types, and sorted unique `(tick, trace_id)`
keys. Retrieval scores every record with a bounded comparison pass, retains a
compact `(tick, trace_id, context width)` receipt for every scanned record,
and preflights only the returned records before constructing their
`EpisodicMatch` values. `arbitrate` checks exactly the properties the contracts
do not themselves enforce: feature-name and outcome-ID uniqueness plus every
cross-object consistency rule; per-object revalidation of frozen inputs is
gone.

The outbound encode boundary is strengthened, not weakened. `encode_*`
functions now encode, decode the payload back, and require equality: the
round trip re-runs `__post_init__` for every nested struct with no
hand-written traversal to drift from the contracts, and equality proves the
encoding canonical. A frozen value mutated in place is caught there, at the
moment it could leave the process.

Retrieval work is charged as the algorithm performs it: a scan term of
2 x (query + context) per record, capped at 65,536 as before, plus a
construction term for the records actually returned, capped at
`_MAX_RETRIEVAL_RESULTS x _RETRIEVAL_RECORD_VALIDATION_PASSES x
_MAX_RECORD_WORK` = 8,388,608. The receipt and returned records reproduce both
terms, so `unit_cost` must equal their exact sum; work for nonmatching scans
cannot disappear at validation or encode time. The total is allowed up to the
derived combined maximum of 8,454,144 rather than being compared with the
scan-only cap. Because the construction cap is derived from the admission
bound rather than chosen, admission and retrieval compose by construction:
any batch of admitted records that retrieval can return fits the cap, so a
legitimately filled memory is always queryable. The worst-case scan — 256
records with 64-feature contexts against a 64-feature query — lands exactly
on the scan cap.

## Consequences

Filling to capacity 256 drops from 10.1s to 0.13s (77x) and is linear
(~n^1.1); one query drops from 92ms to 9ms; arbitration falls from 3.5ms to
2.7ms per 64-candidate call. Episodic recall stops being a floor under every
M2+ experiment that uses it.

What is given up is precisely the ability to detect `force_setattr`
self-mutation *between* construction and the encode boundary. Tests that
pinned that detection now pin the same guarantee at encode, where the round
trip reports the corruption. A decode-boundary test poisons canonical bytes
and proves the nested validators still fire there, which is the property the
removed loops silently depended on. Retrieval determinism is unchanged: the
sort key `(-score, -tick, trace_id)` is injective because trace IDs are
canonical episode/tick derivations, so smaller limits return exact prefixes
of larger ones, and that is now pinned by test as well. The scan receipt is
bounded by recorder capacity, canonically ordered by the recorder key, and
contains only the metadata needed to reproduce scan work.

The retrieval work model in ADR-026 is superseded by the split scan and
construction charges above; ADR-026's storage and scoring semantics are
otherwise unchanged. Reintroducing wholesale revalidation, changing the caps,
or moving a validation boundary requires a new decision record.
